# trendradar contract (v1)

This directory is the **single source of truth** for the data shapes shared by:

- the Go core (`github.com/morehao/trendradar`), and
- the DSH plugin's npm package, which bundles a snapshot of this directory.

There is deliberately **no standalone contract npm package**: the only JS
consumer is the DSH plugin, so the contract ships inside that plugin's package.
The core publishes `CONTRACT.sha256` as a Release asset; the plugin records the
expected hash in its own `contract/UPSTREAM.json` and its CI compares the two.

## Files

| File | Purpose |
|---|---|
| `schema/model.v1.json` | `RepoSnapshot` / `RepoDigest` (domain model) |
| `schema/ipc.v1.json` | Envelope: `RunRequest`, `RunResult`, `ErrorInfo`, `State` |
| `schema/digest.v1.json` | Rendered digest document |
| `schema/api.v1.yaml` | OpenAPI 3.1 for `trendradar serve` |
| `fixtures/digest-normal.json` | Happy path, 4 languages |
| `fixtures/digest-degraded.json` | Fallback path, `degraded: true`, `source: search-api` |
| `fixtures/digest-empty-lang.json` | Only `all` / `unknown` languages present |
| `CONTRACT.sha256` | Stable hash of `schema/` + `fixtures/` |

## `CONTRACT.sha256` format

Generated by `make contract-hash` (Go tool at `tools/contracthash`). Algorithm:

1. List every file under `schema/` and `fixtures/`, as forward-slash paths,
   sorted lexicographically.
2. For each file, emit a line `<sha256-hex>  <relative-path>`.
3. The final line is `aggregate: <sha256 of the concatenated per-file lines>`.

## Version rules

- Adding an **optional** field is a minor change: consumers must ignore unknown
  keys (only `RunRequest` uses `additionalProperties: false`).
- Removing/renaming a field, changing a type, or tightening validation is
  **breaking**: bump `ipcSchema` / `digestSchema` and update both sides.
- `fixtures/` are consumed by both Go and TS test suites; keep them valid against
  the schemas.

## Regenerating

```bash
make contract-hash   # rewrites CONTRACT.sha256
```
